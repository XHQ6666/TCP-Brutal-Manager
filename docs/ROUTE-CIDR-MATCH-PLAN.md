# 路由 CIDR 范围匹配调整计划（待逐项确认）

## 目标

保留单条 Brutal CIDR 规则。指定 interface 或 table 时，允许 Go 给该 CIDR 范围内的已有路由应用 Brutal 拥塞算法和对应 lock 位，解决 Tailscale 只有节点 /32 路由时整条 /10 规则被跳过的问题。

## 已明确的方向

- 默认允许范围匹配，不再要求必须存在唯一精确 Prefix 路由。
- 匹配范围由业务规则 CIDR、地址族、table 和 interface 共同约束；同时配置 table/interface 时两者均须满足。
- 候选路由必须完全包含在业务 CIDR 内；不修改覆盖范围更大的路由，也不跨地址族。
- 不创建 /10 路由，不拆分 /10 Brutal 规则，不修改 Tailscale 节点路由的目的地址或出口。
- 单条规则可显式启用严格模式 route_strict=true，仅匹配精确 CIDR；默认 false，严格模式也处理全部符合条件的精确候选。
- 无 table/interface 的规则继续交由 brutalctl 管理普通路由。
- 沿用规则 lock 与 Route lock 联动；写前重读、写后验证，保留其他路由属性和其他 metrics 锁位。
- 清理仅移除仍匹配 Go 写入值的拥塞算法和对应 lock 位；路由本身保持。

## 待确认事项（按项提问）

1. 已确认：精确 CIDR 路由和范围内更具体路由全部处理，避免 /32 优先命中导致属性未生效。
2. 已确认使用明确的严格路由字段 route_strict，默认 false；true 仅允许精确 CIDR。
3. 已确认：全部符合条件的路由都处理；严格模式同样允许多个精确候选。多路径路由按第 8 项约束处理。
4. 已确认：指定 table/interface 但没有候选时，Brutal 规则照常添加或更新并强制 noroute；报告退化，Run 在路由出现后自动补充属性。旧属性清理规则另行明确。
5. 已确认：重叠业务 CIDR 匹配同一 Route 时，由更具体的业务 CIDR 决定 Route lock；各 Brutal 规则保留自身 Rate/lock。相同业务 CIDR 的参数冲突沿用现有隔离机制。
6. 已确认：逐 Route 隔离局部失败，成功项保留并继续其他 Route；失败项保留原状、重试并报告退化（退出码 7），不回滚成功项。DNS 地址换组仍须整组新地址成功并验证后才删除过期旧地址。
7. 已确认：Route/Link 事件重新计算匹配集合，新匹配路由补属性，已删除路由不重建；仍存在但退出匹配集合的路由，只有属性仍匹配 Go 写入值且没有其他有效或受保护来源需要时才清理。事件使用已有 DNS 结果，不重新查询 DNS。
8. 已确认：多路径路由指定 interface 时要求所有下一跳都符合该接口，否则跳过该 Route 并报告退化；仅指定 table 时允许修改整条多路径路由，完整保留所有下一跳。
9. 已确认：升级记录为业务规则与多条 Route 的关联，保存每条 Route 身份、Go 写入值及共享来源。有效旧记录备份后兼容迁移，不因升级 Flush；无法可靠识别的旧 Route 记录保留待核对并报告退化，其他独立规则继续。记录损坏/丢失的既有恢复机制保持。
10. 已确认：check/diff/status 逐 Route 展示业务 CIDR、实际路由 CIDR、table/interface、route_strict、计划修改或跳过原因，并汇总匹配情况；只读命令展示当前状态与计划，不声称实际执行成功。Apply/Run 执行结果另汇总成功/失败数量。独立测试表覆盖范围匹配、严格模式、重叠、多路径、事件维护及记录迁移；Skyline 实测另行批准。

## 实施范围

- config/rules 模型：严格字段、校验、去重与冲突比较。
- route 匹配：CIDR 包含关系与精确模式，候选列表及稳定路由身份。
- manager：单 Prefix 对多 Route 的计划、执行、验证、来源保护及共享属性清理。
- state：保存每条被修改 Route 的身份、写入属性及全部使用来源；升级兼容旧记录，不因格式升级清空规则。
- Run：路由事件只重新匹配与维护属性，不重复触发 DNS。
- 文档与示例：替换唯一精确匹配的旧描述，解释严格模式及范围约束。
